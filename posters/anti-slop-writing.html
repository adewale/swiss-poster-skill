Anti-Slop Writing

Core rule
Sharp detail beats
inflated significance.
Before writing, answer
  1. What is the exact point?
  2. What concrete detail proves it?
  3. What sentence machinery is making it feel true?
  4. What should the reader remember?
AI writing often fails by doing this
less detail, more importance
Fix by doing this
more detail, earned importance
Inflated significance: cut
Detector hit: check the sentence
Mechanism: write this instead
Relation that earns the word

01Replace importance with mechanism

BeforeThis underscores the importance of durable execution.

AfterThe workflow can fail on step 4, retry only that step, and keep the previous outputs.

The rewrite names the behavior that makes execution durable.

02Cut safe essay voice

BeforeIn today’s rapidly evolving landscape, teams need robust solutions that empower developers to build seamless experiences.

AfterA frontend developer can ship a shared cart without running a sync service.

The rewrite names an actor, an action, and a concrete result.

Keep

03Treat hits as hypotheses

“The queue is robust because each job has an idempotency key, a retry receipt, and a dead-letter cutoff.”

Why: “robust” is an engineering qualifier earned by the deduplication, retry-tracking, and dead-letter mechanisms.

04Replace rhythm with relation

BeforeThe point is not the pelicans. The point is the process.

AfterThe pelican is useful because it gives the process a small, inspectable carrier.

Decorative antithesis: neither side is evidenced. The rewrite keeps the concrete example and explains how it supports the larger claim.

Ask-author

05Ask the author

BeforeClaude Code turned the cover-image generator from a someday-item into an afternoon.

AfterAsk author: which coding tool? Cursor, Claude Code, Copilot, Aider, other?

The source never names the tool. The rewrite picked one and shipped it as fact.

06Return to the carrier

BeforeA benchmark is stronger when you can inspect the run that produced it.

AfterBecause the pelican project is small enough to inspect and strange enough to remember, it works as a compact carrier for the larger claim: a benchmark is stronger when you can inspect the run that produced it.

The conclusion returns to the memorable object before stating the transferable claim.
